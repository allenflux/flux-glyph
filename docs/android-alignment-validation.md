# Android 字体候选匹配验证

本轮增加 32×32 字形的半像素平移比较，修正原生字号和重采样产生的栅格对齐偏差。平移后落到边界外的笔画仍参与归一化，避免通过丢弃笔画降低距离。原参考字形、苹方校准距离和门槛不变；其它字体仍须完整分字且三个图像视图的第一候选一致。

## 冻结的 36 张端到端输入

输入文件、真值和样本协议均未修改。旧结果取本轮前的 `accuracy-report.json`；新结果由原 `accuracy_eval.py` 全流程执行，包含检测、OCR、分字、字体候选。

| 指标 | 原匹配 | 半像素候选匹配 |
|---|---:|---:|
| Android 四家族正确 / 全部 | 16/24 | 19/24 |
| Android 错误命名 | 1 | 0 |
| MiSans 正确 | 3/6 | 5/6 |
| OPPO Sans 正确 | 2/6 | 3/6 |
| HarmonyOS Sans SC 正确 | 5/6 | 5/6 |
| Noto Sans CJK SC 正确 | 6/6 | 6/6 |

Android 的 5 个剩余失败均为拒识。整体仍有 2 个宋体样本的分字几何问题。本改动没有改变分字。HarmonyOS 与 OPPO 各有一个旧的正确样本变为拒识，因此总体提升不代表每个输入都改善。

## 额外的独立渲染检查

在算法候选对比之后，预先声明 6 段新文本 × 6 个此前未用的字号（19、23、29、35、41、47）× 2 种背景 × 6 家族，运行 432 组完整原生字框检查。字体文件 SHA-256 和 PostScript 字面均按原字体清单校验，未使用原 36 张截图的文本或字号。

| 字体 | 原正确 / 72 | 新正确 / 72 | 原错误命名 | 新错误命名 |
|---|---:|---:|---:|---:|
| Noto Sans CJK SC | 63 | 70 | 0 | 0 |
| HarmonyOS Sans SC | 46 | 63 | 3 | 1 |
| MiSans | 64 | 62 | 0 | 0 |
| OPPO Sans | 41 | 57 | 4 | 0 |
| PingFang SC | 71 | 72 | 0 | 0 |
| Songti SC | 69 | 69 | 0 | 0 |

Android 合计从 214/288（74.3%）升至 252/288（87.5%），错误命名从 7 降至 1。MiSans 的额外检查有小幅回退，当前实现仍保留拒识，没有以多数投票代替三个视图的一致要求。

复跑：`.venv-dev/bin/python tests/android_alignment_eval.py`。须具备原清单声明的源字体文件；逐样本结果、源字体校验和和字形像素校验和见 `android-alignment-validation.json`。该检查只度量受控渲染字框的匹配，不包含检测/OCR/分字，也不代表真实 Android 或支付宝截图的识别率。真实截图仍需要独立字体真值验证。
