# 相似字体的神经网络复核

R19 的类别分数只在八个已知字体中竞争。相似的未覆盖字体可能得到很高分；已有字体的裁图被缩放、压缩后，也可能改变首选类别。不能用 PingFang 或 SF Pro 预测来确认设备系统，更不能把 `1.0000` 当成准确率。

本轮在 R19 之后增加独立训练的九类字体 CNN，以区域像素复核主模型。九类包含原八类和 Roboto。原字体/字号 ONNX 与未知字体拒识 ONNX 保持原始字节，复核网络有自己的可训练图像编码器和分类头。它不是字形模板比对，不输入 OCR 识别文字、脚本或设备平台。

流程为：文字区域检测 → 原未知字体拒识 → 原字体模型与新复核模型 → 两者同意且各自通过门槛时输出候选。分歧时返回 `uncertain`，字体名和字号为空，页面分别展示两网候选及评分。复核网络判到主模型范围以外的类别并通过门槛时，返回未知字体。Roboto 在这里是额外竞争类别，不宣称主模型已经支持正式命名它。原图文字颜色独立测量。

## 数据和训练

[新数据](font-sans-data.md)来自 420 页受控原生 iOS Simulator 截图。包含多种轻字重，以及 Roboto 的两个宽度和五个字重。所有类别使用同一采集应用和渲染方式；每行有 CoreText 实际字体及来源核验，不能由字体请求名称推定实际标签。未上传用户截图，也不把用户图中的字体猜测用作训练真值。

`training/prepare_sans_views.py` 对每个已有来源先保留固定分区，再生成四种视图：原图、缩小一半、缩至 75% 后 JPEG 75 压缩、原尺寸 JPEG 75 压缩。字号真值按实际竖向缩放比例调整。所有衍生图继承原图分区；四个视图不是四个独立样本。

训练锚点从 R17 各字体固定随机选择最多 384 行，共 2,788 行；再加入 3,599 行新原生训练区域。训练包含 25,548 个视图、62,346 个图块。校准含旧 1,093 行和新 719 行的四视图，共 7,248 个视图、17,662 个图块。根清单和各分区清单分别不可变；测试视图只有校准选择通过并冻结后才能生成。

训练入口为 `training/train_sans_verifier.py`，在本地 Apple GPU 上训练独立网络；按字体平衡采样，原图视图占 40%，其余各占 20%。监督目标来自原生字体标签；清晰的旧训练锚点还用冻结的 R17 网络作蒸馏约束，降低原本正确字体被新网络拦截的风险。字号输出只作辅助训练，不替换线上字号模型。

首轮训练 4,000 步，使用统一学习率；随后 `training/continue_sans_verifier.py` 从首轮选中权重追加 8,000 步，将分类头初始学习率设为 0.0005，其余设为 0.0001，并继续教师蒸馏。两轮均保留完整选择历史和文件绑定。续训复用经过来源校验的旧模型校准输出，未重新选择或修改主模型。

训练阶段策略固定，复核温度 1.0、分数门槛 0.5、前两名差值 0.01、图块一致性 0.7。原图锚点正确命名保留至少 98%，各系统字体至少 95%，退化图正确命名保留至少 85%；错误命名须减少至少 20%，复核网络对 Roboto 的独立召回须至少 80%。后者包含旧拒识网络已经拦截的区域，不等于新增拦截率。

首轮失败审计发现，损失的 36 个原有正确结果中，32 个整体第一候选仍正确，仅因图块一致性不足被拦截。另设独立的校准步骤：在同一个已训练检查点上只比较新复核网络的图块门槛 0.7 和 2/3；分数、差值、温度及上述全部发布条件保持不变。这两个方案仍未通过原 Roboto 独立召回 80% 的要求；原训练和这次校准报告均保留失败，不能据此声称完成了 Roboto 正式识别。

在看到上述校准结果后、打开测试集之前，另外声明针对实际错误命名的发布协议：保持上述正确结果保留要求和总错误命名减少要求，将 Roboto 的发布指标改为“拦住 R19 已经接受的错误字体名至少 80%”。分母只包含 R19 错误接受的 Roboto 区域，分子是其中不再被错误命名的区域；旧模型已经弃权的区域不能算新增拦截。独立 Roboto 召回仍完整报告，但不再作为这个辅助复核功能的发布门槛。这是校准阶段修订后的评判目标，不能声称原始预定方案通过，也不能把旧失败结果改写为通过。

新协议使用同一已冻结权重，仅在上述两个图块门槛中校准；优化器步数为零，不允许两个窗口一对一分歧通过。原主模型的 0.7 门槛始终不变。新清单绑定旧失败报告、原检查点和两个方案，模型、门槛、指标及清单全部冻结后才生成测试视图。测试只评估一次，不能根据测试结果继续调门槛并报告为未见测试。

## 导出和使用

`training/export_sans_verifier.py` 导出新的 `verifier.onnx`，用未更改的 PyTorch GroupNorm 作独立参考，检查完整校准集数值和最终判定，以及不同 batch 大小。导出只改变算子计算表示，不改变训练权重。

元数据算法为 `region-cnn64x256-consensus-v3`。三个 ONNX 均绑定 SHA；任何模型缺失、哈希不符或非法输出都不能绕过复核继续命名。独立下载包包含三个模型和完整推理代码，使用方式仍是 `python predict.py text-region.png`，推理只依赖 ONNX Runtime、NumPy、Pillow。

这轮验证反映受控模拟器字体与图像退化的表现，尚不能证明安卓原生渲染或任意第三方主题字体的准确率。两个模型仍可能共同犯错。用户裁图只用于本地定性回归，不能作为有真实字体标签的准确率测试。
