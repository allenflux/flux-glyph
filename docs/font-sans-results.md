# R20 字体复核验证

R20 增加一个在本地训练的字体复核 CNN，降低相似字体得到高分后被错误命名的情况。原 R19 字体/字号模型和未知字体拒识模型的文件字节不变。字体名称只在两网首选一致、各自通过门槛时作为候选输出；分歧时显示双方评分，不确认字体和字号。

## 冻结测试结果

新采集的 60 页、720 个区域作为新测试来源；另外复用 R17 的 1,104 个测试区域作回归。每个来源有原图、半尺寸、75% 尺寸加 JPEG 75、原尺寸 JPEG 75 四个相关视图，共 7,296 个视图。新模型、投票门槛、发布指标和代码在测试前冻结；只运行一次正式测试，之后没有调整权重或门槛。

| 字体区域测试指标 | R19 | R20 |
|---|---:|---:|
| 全部错误命名 | 493 | 71 |
| 全部正确命名 | 4,898 | 4,816 |
| 原有清晰回归区域正确命名 | 1,014 | 998 |
| 其中 PingFang 正确命名 | 345 | 345 |
| 其中 SF Pro 正确命名 | 124 | 124 |
| 其中 Helvetica 正确命名 | 48 | 48 |
| 缩放、压缩视图正确命名 | 3,464 | 3,401 |
| Roboto 被错误命名为已覆盖字体 | 93 | 12 |

总体错误命名减少 **85.6%**，原有正确命名保留 **98.3%**。新增弃权包括 82 个原本正确的结果，不能描述为识别覆盖率提高。清晰回归区域的正确命名保留 98.42%，三个系统字体在这个子集中原本正确的结果全部保留；原 SF Pro 子集里的一处错误仍然存在。

仅看新采集的 720 个来源及其 2,880 个视图：错误命名 **368 → 49**，正确命名 **1,484 → 1,469**。复用的 R17 来源四视图则为错误 **125 → 22**、正确 **3,414 → 3,347**。不能把复用来源说成全新未见测试，也不能把四个相关视图算作四张独立截图。

本轮按真值区域裁图评测字体网络，没有重新验收整页文字检测。上述 1,014 等基线数与历史整图检测流程的 1,011 等成绩不是同一输入口径，不能直接相减。所有有字体真值的新截图均来自受控 iOS Simulator，包括应用加载的厂商字体；尚无 Android 原生字体准确率结论。

## 训练与判定目标

本地实际运行 4,000 步首轮训练，再运行 8,000 步续训；续训选中第 7,500 步，选中权重对应累计 11,500 步。主模型和拒识网络未重新训练。

原训练标准和两个投票门槛的校准均失败，报告保留失败。选中权重在复核投票门槛 2/3 下，CAL 的独立 Roboto 正确且过门槛为 **183/240（76.25%）**，未达到原 80% 要求。

查看 CAL 后、打开 TEST 前，另设针对实际错误命名的协议：Roboto 只作为额外竞争类别，要求拦住旧模型已接受的错误命名至少 80%，不宣称正式支持识别 Roboto 名称。其他保留率和总错误减少要求不变。没有再训练，仅在预先声明的 0.7 和 2/3 两个复核投票门槛中选择；原主模型的 0.7 保持不变。

新协议的 CAL 新增拦截为 **88/95（92.63%）**；冻结 TEST 为 **81/93（87.10%）**。旧模型本来已经弃权的区域不计入新增拦截。TEST 的独立 Roboto 正确且过门槛为 **194/240（80.83%）**，这是单独诊断，不能据此把旧 CAL 的失败改写成通过。

完整指标、失败历史、数据/代码/权重 SHA 和测试前冻结记录见 [验证清单](sources/sans/VERIFICATION.json)。算法和复现入口见 [复核训练说明](font-sans-verification.md)，数据来源见 [采集说明](font-sans-data.md)。

## 用户示例和功能检查

用户提供的页面缩略图仅用于本地定性回归，没有字体真值，没有上传或加入训练、校准：

- 最新金额裁图原为 SF Pro 候选，新版变为两网分歧；不能据此认定真实字体是复核网的 Alipay Number 候选。
- “全部账单”裁图变为两网分歧。
- 较早截图中的细字标题仍为 PingFang 候选，未解决；两个模型一致也不能证明字体身份或手机系统。

ONNX 与原始 PyTorch 在全部 7,248 个 CAL 视图上最终判定一致，最大 logits 绝对误差为 `3.8147e-05`；512 个图块在 batch 1、7、32、128 下检查通过。原字体及拒识 ONNX 的 SHA 保持原值。

下载包含三份 ONNX，7 个本地输入使用独立 `predict.py` 的完整 JSON 与项目推理一致；无 PyTorch、项目包或 OCR 依赖。700 项功能测试、114 项子测试及静态 UI 检查通过，31 项测试因开发环境缺少可选依赖跳过。网页还通过中英与不同宽度的分歧/拒识显示检查。字号仍由原模型估计，颜色由原图测量，本轮不宣称二者精度提高。

本地 Docker 的真实接口使用三个预先生成的非用户字体图完成检测、区域推理和下载检查，API 区域判定与本地同模型一致。下载 ZIP 为 4,092,624 字节，SHA256 为 `cd6faecef0ebbf85c8216a05c220d4a940da0c48c2e12d56e3320af6ebbac78b`。这些小图只验收服务功能，不代表完整截图性能或额外准确率成绩。
