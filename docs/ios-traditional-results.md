# R17 简繁体、英文和数字验证

本地 Docker 已运行 `r17-ios-hant-region-v1`。字体模型下载位于上传区上方，包含 ONNX、推理代码及使用说明。默认 `models/ACTIVE.json` 选择随源码提供的完整 R17 包，标准 Compose 和本地 iOS Compose 都挂载 `./models`，不依赖本机训练的 `artifacts/`。

本次未更新线上 `allenflux.tech:9000`；此前只读检查显示线上仍加载 R14，字体下载接口返回 `available:false`。远程检查的自动审批随后因账户用量限制失败。下述成绩和下载验证均来自本地 R17。

## 训练与分类范围

新采集 1,000 张 iOS Simulator 实际截图、10,941 个原生文字区域。800 页用于训练、100 页校准、100 页为本轮新固定测试。全部区域的原生字体、字号、来源、PNG 和像素校验通过，没有回退字体或被拒绝的区域；新旧规范化文字组合交集为零。完成 4,000 次参数更新，校准选择第 4,000 步，8,744 个训练区域全部被采样。测试在选择及门槛冻结后执行。

模型包含 PingFang、SF Pro、Helvetica，以及 HarmonyOS Sans SC、MiSans、Noto Sans CJK SC、OPPO Sans、Alipay Number。前三者来自系统字体，其余由采集应用加载；**Alipay Number 是应用自带数字字体，不是 iOS 系统字体**。这些外部字体在 iOS 中渲染，本轮没有使用 Android 截图训练。

原生 SC／TC／HK 中存在相同字形，故输出 PingFang 字体族，原生子类仍保留为真值。模型不会因为文字是繁体就推断 TC／HK。网络输入只有区域像素，PP 模型只找位置，运行时不识读文字、不做逐字切分、不与参考字库比较。详见 [采集证据](ios-traditional-capture.md) 与 [训练流程](ios-traditional-training.md)。

## 完整原图结果

对固定 100 张新测试原图运行实际检测、区域 CNN、字号回归和颜色测量。检测框与原生墨迹框按几何位置一对一匹配，标签只用于评分。

| 类型 | 区域 | 字体正确 | 字体错误 | 待确认 | 返回名称覆盖率 |
|---|---:|---:|---:|---:|---:|
| 简体 | 343 | 309 | 0 | 34 | 90.09% |
| 繁体 | 361 | 321 | 0 | 40 | 88.92% |
| 英文 | 200 | 191 | 1 | 8 | 96.00% |
| 数字 | 200 | 192 | 0 | 8 | 96.00% |
| 合计 | 1,104 | 1,013 | 1 | 90 | 91.85% |

1,104 个区域全部检出，没有额外框。已输出字体名称的准确率为 **99.90%（1,013／1,014）**；全部区域中正确命名比例为 **91.76%（1,013／1,104）**。唯一错误是英文 SF Pro 被命名为 Helvetica。“待确认”仍表示没有通过当前候选门槛，不能计作正确名称。

字号可估计 1,014 处，全部相对误差不超过 10%；平均绝对误差 **0.757 px**、平均相对误差 **1.31%**。字号单位是截图像素，不是 iOS pt。颜色 1,104 处全部可测量，并与原生可见 RGB 一致。运行时识字器、字符切分和旧单字分类器的受保护调用次数均为零。

仅使用原生裁图、隔离检测影响时，字体结果为 1,016 正确、1 错误、87 待确认。该口径与上表的完整原图成绩分别报告。

## 导出、下载和页面验收

稳定 ONNX 与原始 PyTorch GroupNorm 在 64 个 calibration 区域、179 个图块上比较，batch 为 1／7／32／128。两个原始输出、区域聚合分数、字号及接受决定均通过原定容差；没有修改权重或门槛。最大 logits 差为 `3.24249e-5`，最大字号差为 `2.14577e-5 px`。

最终字体 ONNX SHA256：`bff569708afbb127222885539914942f9d958f46c8c11bfb9ace80784f70916b`。

实际从本地 Docker 下载字体 ZIP，共 **1,361,929 字节**，核验完整 ZIP 及每个成员的 SHA256。ZIP SHA256 为 `c312975ef5694d05fb4facec785946635caf91fa73b0c8daf7a1293049fbe393`。解压到项目目录外、移除 `PYTHONPATH` 后运行附带 `predict.py`：按预定类别顺序选择的 11 个固定测试样例全部给出正确字体及颜色，覆盖 SC／TC／HK 的简繁体、SF Pro 和 Helvetica 的英文／数字、Alipay Number 数字。样例不按预测是否成功筛选，这项验证也不代替完整测试成绩。

实际 API 上传原生完整截图，返回 12 个区域，顶层 `ocr_performed:false`，每区文字为空、`glyphs` 为空，字体方法为 `region_neural_network`。下载包记录系统／应用字体来源及 PingFang 分组，不含识字器或参考字库。

真实 Chrome 桌面 1280×900 和手机 390×844 均通过：下载置顶且可用、来源分组、中英说明、实际上传、区域详情、字号与颜色、真实队列进度、JSON 复制及原尺寸 PNG 下载。浏览器产品错误为零。Python 套件 **357 项通过、18 项跳过**；另在 PyTorch 环境完成 **8 项区域网络训练测试**。跳过项主要依赖可选训练环境。

## 范围与交付

测试是受控生成页面的原生模拟器截图；新文本和新截图仍属于与父模型相同的渲染环境，不能写成真实 App 或物理手机准确率。历史桌面渲染的 67 张回归样例中，23 正确、28 错误、8 个已知字体待确认、2 个未知字体拒识、6 个检测数量不符。14 个未知字体样例中仍有 11 个被误命名、2 个拒识、1 个检测数量不符。**当前版本仍不能可靠拒绝未知字体**；这组回归没有用于调整训练或门槛。

默认完整包保存在 `models/releases/r17-ios-hant-region-v1`；旧 R16 与根目录 R14 保留。单独字体下载包是 `artifacts/flux-glyph-r17-font-onnx.zip`；源码和完整模型的部署包由 `scripts/build_release.py --model-root models` 生成。两个 ZIP 的用途不同，前者处理文字区域裁图，后者运行完整网站/API。

结构化指标及证据索引见 [JSON 报告](ios-traditional-results.json)。全部逐页评估、原始 SHA 与截图证据保存在本地 `artifacts/ios-hant-region-v1/`。
