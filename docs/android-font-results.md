# 安卓字体模型验证记录

当前 Android 下载版本为 **`android-open-fonts-v1-preview`，实验候选模型**，使用第一轮已冻结的 ONNX。它可由用户主动选择和下载试用，尚未通过原定稳定版验收。默认 iOS 仍使用 R20。

各轮结果分别保存。校准结果用于选择模型和门槛，独立测试用于检查稳定版要求；开放实验候选不把失败测试改名为通过，也不把后续训练见过的数据继续当作未见测试。第二轮、第三轮和 OVR 实验均未发布，其扩充数据和训练步数不属于当前下载模型。

## 第一轮：稳定版验收失败，以实验候选开放

本地 Android API 35 原生采集共 800 页、9,600 区域：训练 600 页，校准和测试各 100 页。完整来源为 35 个字体实例，训练使用其中 33 个：九个已知类别的 26 个实例，加上七个未知字体实例；校准和测试各另留一个未知字体实例。采集应用显式加载字体资产，来源不是厂商默认字体或真机截图。

独立 TEST 为 100 页、1,200 个原生区域及其 4,800 个相关视图。原尺寸与三种缩放／压缩视图并非四倍独立样本；未知区域占设定测试混合的 25%，不是线上真实字体分布。评估使用给定原生字形边界的裁图，不代表整图文字检测加字体识别的端到端准确率。

本机 MPS 实际执行 6,000 个 AdamW 更新，选择第 6,000 步。原 PyTorch、缓存 MPS 和 ONNX 在全部 4,800 个校准视图上的字体命名及字号可用性一致，字号差异最多 0.01 px。ONNX SHA-256 为 `c095f67c4763cbec7055ac04f706c5dcbb9ad4b8b72e43c6beedfa53851ec17a`。

| 指标 | 校准 | 独立测试 |
|---|---:|---:|
| 总视图数 | 4,800 | 4,800 |
| 已知字体正确命名 | 2,533 / 3,600 | 2,465 / 3,600 |
| 已知字体错误命名 | 30 | 23 |
| 未知字体错误命名 | 21 / 1,200 | 174 / 1,200 |
| 所有命名结果的精度 | 98.03% | 92.60% |
| 已知字体正确命名覆盖率 | 70.36% | 68.47% |
| 原尺寸已知字体首选准确率 | 95.22% | 94.44% |
| 未知字体未被命名 | 98.25% | 85.50% |
| 正确命名的字号中位相对误差 | 2.82% | 3.03% |
| 正确命名的字号 P90 相对误差 | 7.23% | 7.25% |
| 稳定版验收 | 校准通过 | **未通过** |

两组字号指标都仅计算正确命名的区域，且这些区域全部输出了字号。不能据此推断未知字体或不确定区域也有同样的字号精度。两组预处理均无拒绝项。

第一轮 TEST 的未知来源只有完全留出的 Smiley Sans／得意黑：174 / 1,200 个视图（14.5%）被错误命名，其中文泉驿 99、ZCOOL QingKe HuangYou 42、Roboto 30、Noto Sans 3。85.5% 的“不命名”包括 1,008 个不确定和 18 个显式未知结果，显式未知类召回仅 1.5%，不能写成“识别出了 85.5% 的未知字体”。已覆盖字体中，文泉驿的正确命名覆盖率为 46%，也未达到每类 50% 的要求。

整体命名精度 92.60% 的分母是全部 2,662 个命名结果，其中 2,465 个正确、197 个错误。仅在真值属于九个已知类别且已输出名称的 2,488 个结果内，条件精度为 99.08%；这个子集数字不能作为总体准确率宣传。模型分数也不是正确概率。

第一轮冻结权重现以 `android-open-fonts-v1-preview` 提供主动试用，该开放决定作于已知首轮 TEST 失败之后。模型信息接口与 ZIP 内元数据声明 `release_tier: experimental`、`test_passed: false` 和 `stable_validation_passed: false`，`validation` 提供评测说明；预测 API 与 CLI JSON 使用 `model_release_tier: experimental` 和 `stable_validation_passed: false`。网页同样明确标示实验候选。使用者获得的是字体候选，不是具体字体文件、厂商或系统来源的确认。原验收策略和失败报告保持不变：`artifacts/android-font-v1/run-v1/TEST.json`；校准、导出证据分别为同目录的 `SELECTION.json` 和 `PARITY.json`。

## 第二轮的隔离原则

第一轮结果已经用于发现问题，后续对它的复测只能称开发回归。补充训练时可以使用得意黑，但必须明确它不再是本轮未见字体；新的未知字体评估另取此前未参加训练、校准的实际字体家族。

新来源排除与已有已知类共享字形的别名／衍生字体，例如不能把 Klee One 与基于它的 LXGW WenKai 强行分为未知和已知。新文字还须排除第一轮全部分区已使用的规范化文字。来源登记、训练、校准和新测试仍各自绑定文件及源码 SHA；不根据新测试结果改门槛后重报同一测试为独立通过。

## 第二轮：校准未通过，未打开新测试

[第二轮来源登记](sources/android-v2/README.md) 扩充到 63 个静态 face。Android 原生采集 1,300 页、15,600 个区域，训练／校准／测试分别为 1,000／150／150 页。训练可用视图 47,988 个，另有 12 个未知字体视图因墨迹过小被拒绝；校准 7,200 个视图无拒绝。新文字与第一轮全部文字隔离，未知类按真实字体家族隔离。

本地 MPS 执行 10,000 个优化步骤；固定网格共检查 600 组步骤与门槛组合，没有组合同时达到原定验收要求。保持已知覆盖至少 70% 和每类覆盖至少 50% 时，最高命名精度仅 91.66%：3,969 个正确名称、24 个已知字体错误名称、337 个未知字体错误名称。若要求命名精度至少 98%，最高已知覆盖降至 13.67%。

这说明只提高分数门槛不能同时解决错名和覆盖问题。上述覆盖达标点的原尺寸已知首选准确率为 96.30%，不能将它作为包含未知字体的整体识别精度。原始训练按十个输出类别等量采样，使九个实际未知家族共分 10% 的训练批次；后续将以同一训练数据强化未知家族采样，继续只按校准集选择。

第二轮没有导出、激活或部署模型，新的测试像素尚未进入预处理和推理。精简证据见 [EXPERIMENT_V2.json](sources/android-v2/EXPERIMENT_V2.json)，本地完整冻结记录位于 `artifacts/android-font-v1/run-v2/`。

## 第三轮：均衡未知样本和 OE 未改善验收，未发布

从第二轮选中的第 8,000 步权重继续，在本地 MPS 完成 6,000 个新增优化步骤。每批已知／未知各 32 个区域，未知按真实家族、字体文件和 TTC face 均衡，四种视图仍按 40%／20%／20%／20% 抽样。十类交叉熵和字号损失之外，增加权重 0.5 的未知样本已知头均匀交叉熵，参考 [Outlier Exposure](https://arxiv.org/abs/1812.04606) 的训练思路，并非论文复现。完整继承编码器、十类字体头和字号头，所有参数实际微调。

固定的 360 个校准组合仍全部未通过。保持已知总覆盖至少 70% 和每类至少 50% 时，最高命名精度为 86.00%（3,975 个正确命名、31 个已知错名、616 个未知错名）；精度至少 98% 时，最高已知覆盖仅 4.98%。这比第二轮更差，不能称为提升，也不替代第二轮模型。没有导出、部署或打开新测试。证据见 [EXPERIMENT_V3.json](sources/android-v2/EXPERIMENT_V3.json)。

## OVR 实验：校准未通过，未发布

冻结第二轮选中模型的图像特征和字号参数，只训练九个独立的所属字体神经头，实际完成 4,000 个本地优化步骤。240 个固定校准组合全部未通过：保持已知总覆盖至少 70% 和每类至少 50% 时，最高命名精度为 90.58%（3,944 个正确命名、20 个已知错名、390 个未知错名）；没有组合达到 98% 命名精度。证据见 [EXPERIMENT_OVR.json](sources/android-v2/EXPERIMENT_OVR.json)。

该结构没有导出、部署或读取新测试用于推理。它与第二、第三轮均属于未发布实验，不能宣称已提升当前实验下载版；后续 63 个字体实例的采集来源也不能用于描述第一轮的训练范围。
