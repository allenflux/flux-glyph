# 统一字体模型的训练梯度诊断

2026-09-14，本地 MPS 只读诊断完成。比较对象是线上 R22 的固定检查点，以及完成 2,400 步但未达验收要求的 `native-pairs-v1` 检查点。没有优化器步骤、权重更新、CAL／DEV 推理或 TEST 访问，也没有导出和部署新模型。

## 方法

`training/diagnose_unified_font_gradients.py` 重建上一轮完整的 2,400 步 TRAIN 采样流，预先固定其中均匀分布的 32 批。四个采样器的完整计数，以及 68,712 个有效短行教师标签，与先前保存的训练记录完全一致。每批仍为 96 个回放区域、32 个原生短行、20 个移动端短区域和 16 对字体区域，共 180 行。每个检查点测量 5,760 个抽样行，重复抽样及相关增强不计作独立样本。

两个检查点使用完全相同的输入。`training/font_gradient_diagnostics.py` 将原训练目标拆成八个包含实际系数的项：回放字体监督、短行字体监督、移动端字体监督、字号、教师蒸馏、角度间隔、未知字体约束、字体配对。拆分后的标量总和及梯度总和必须还原原目标。字号头和字体头分别核验；主要诊断对象为共享的 `trunk + style` 参数。

参考梯度 `g_font` 为前三项字体监督梯度之和，包含真实未知字体的监督。对每项 `g_i`，报告强度比 `||g_i|| / ||g_font||`、余弦及方向贡献 `g_font·g_i / ||g_font||²`。零范数的余弦记为未定义。总方向贡献为正，仅表示局部原始 SGD 方向的一阶下降；它不是实际 AdamW 更新，也不能推出多步训练或留出数据的表现。报告中的“移除字号／教师”也只是代数计算，没有执行训练消融。

## 实测结果

以下为共享参数上相对全部字体监督的逐批统计均值；百分比不是损失占比或识别准确率。

| 指标 | R22 | native-pairs-v1 |
| --- | ---: | ---: |
| 字号梯度强度比 | 0.858% | 1.112% |
| 字号方向贡献 | +0.029% | −0.040% |
| 教师梯度强度比 | 6.774% | 27.960% |
| 教师方向贡献 | −1.551% | −0.744% |
| 教师方向相反的批次数 | 28／32 | 22／32 |
| 移动端字体监督方向贡献 | 83.881% | 71.113% |
| 总梯度方向贡献均值 | 1.0149 | 1.0222 |
| 总梯度方向贡献最小值 | 0.9742 | 0.8586 |

全部 64 批的总梯度都与字体监督同向。以单独移动端字体监督为参考时，总方向也全部为正；教师的平均方向贡献分别为 −1.962% 和 −2.319%。因此，虽然确实存在局部冲突，本次抽样没有发现总训练梯度反向或字体监督被大幅抵消的证据。不能仅凭负余弦次数较多，就把既有识别退化归因于教师或字号任务。

新移动端监督在当前更新方向中的贡献较大，也不支持简单认为它因每批只有 20 行而没有足够影响。先前的 TRAIN 拟合改善与 CAL 退化仍需从字形表达、样本覆盖及训练到实际截图的差异继续检查。

## 下一项试验的选择

本次结果不支持直接删除字号学习或教师保留约束。下一项优先检验保留局部笔画细节的单网络结构：维持现有字体分类、字号和颜色输出，检查早期降采样及空间汇聚是否丢失相近字体的细节。结构试验应从固定 R22 初始化，先验证初始输出和新增参数的梯度，再按固定训练预算比较，避免同时更改数据和全部损失系数。

这是后续试验方向，尚未实现或训练该结构。仍要求一个统一 CNN／ONNX、没有平台路由、OCR 只辅助定位。原 53 项 CAL、安卓错误命名为 PingFang／SF Pro／Helvetica 不超过 27、完整 ONNX 一致性及 36 项 DEV 要求不变；TEST 继续封存。已有 CAL 经多轮复用，不能将后续 CAL 数值称为盲测结果。
