# Flux Glyph 交付验证

交付类型：可部署的中文字体识别验证版。网站/API 功能已完成；真实支付宝截图 90% 字体准确率尚未完成验收。

## 完成的功能

上传单张支付宝截图 → PP 框选并识读文字 → 原图像素分字 → 中文字体匹配。可点击框或列表查看区域、单字原图证据、字体名/候选与待确认原因；旁边显示并支持复制格式化 JSON，可下载原始尺寸标注 PNG。白图、蓝图走同一条流程。数字/英文保留框，当前不作其字体判定。结果不作设备推断或截图真伪判断。

模型、网站、API 已迁入本项目，Linux 容器不依赖旧项目、外接硬盘、macOS Vision、在线下载或训练环境。

## 资源测试

在本机 Docker Linux aarch64 容器实测，CPU 上限 2 核、内存上限 1536 MiB、单任务推理。测试用 100 张已有原始截图（50 白图、50 蓝图），额外测试 2000×6000 像素输入。此结果不是云服务器实机性能保证。

| 项目 | 结果 |
|---|---:|
| 100 张原图成功处理 | 100 / 100 |
| 单张推理中位耗时 | 1.45 秒 |
| 单张推理 P95 耗时 | 1.70 秒 |
| HTTP 中位耗时 | 1.63 秒 |
| 容器内存峰值，含文件缓存与大图测试 | 841.2 MiB |
| OOM / 容器自动重启 | 0 / 0 |
| 完整模型文件大小 | 84.26 MB |
| 字体参考包 | 68.08 MB |

[资源明细](resource-validation.json)。字体向量缓存最多 32 个汉字；原图区域按最多 6 个、合计 400 万像素分批处理，单个更大区域独立运行。上传上限 8 MB / 1200 万像素；一次最多识别 200 个区域。资源测试时为一个任务执行、两个排队；本次界面更新将等待容量调至八个，运行任务仍为一个。

## 真实原图的输出覆盖

100 张共检测 3321 个区域，其中 2791 个含中文。输出字体名 1638 个（苹方 977，其他字体候选 661），中文区域命名覆盖率 58.69%。这些原图没有逐框字体真值；这是覆盖率，不能计算真实准确率。目录中的截图可能包含伪造图，也不能用设备标签代替字体真值。

## 有字体真值的受控评测

使用固定 36 张图片、6 个已核验源字体，组合 24–42 像素字号、白/蓝背景和压缩条件。修复分字后：

| 口径 | 结果 |
|---|---:|
| 已输出字体名的正确率 | 27 / 28 = 96.43% |
| 同时要求裁字证据完整的严格正确率 | 26 / 28 = 92.86% |
| 输出覆盖率 | 28 / 36 = 77.78% |
| 全部样本字体名正确率 | 27 / 36 = 75.00% |
| 全部样本严格正确率 | 26 / 36 = 72.22% |
| 识字完全正确 | 36 / 36 |
| 分字几何完整 | 34 / 36 = 94.44% |

剩余主要问题是相近字体（特别是 OPPO / HarmonyOS）的区分、低质量字形和字库范围。无法从此小样本结论推断“全部支付宝截图 90% 以上”。[完整精度报告](accuracy-report.md) / [逐样本结果](accuracy-report.json)。验收真实准确率需要独立且来源明确的逐框字体标签；状态栏模型和旧字体模型预测均不作真值。

## 部署

下载部署 ZIP 后解压，在 `flux-glyph/` 下运行 `docker compose up -d --build`，访问 `http://服务器IP:9000/`。模型已包含。服务内存上限给 2 GB 主机留出余量；此验证没有连接或修改用户云服务器。可选令牌见 `.env.example`。

## 简化上传入口更新

公开部署地址保持 `http://allenflux.tech:9000`。支持 `curl -F "file=@./alipay.png" http://allenflux.tech:9000`，无需手写 `Content-Type`、`X-Filename`。也兼容 `POST /upload` 与 `curl -T ... /upload/文件名`。`GET /` 继续显示网站。

三种上传方式均已对本地 Docker 服务实际测试，源图片 SHA 与字体结果一致；原有鉴权、图片限制及排队机制复用。详见 [上传验证](upload-validation.json)。这是代码和本地服务更新，未在远程域名服务器执行部署。

## 排队、进度与双语交互更新

默认一个推理任务运行、八个等待，网页显示服务端队列位置与前方任务数量。排队动画不显示虚构百分比；处理进度来自真实阶段和已完成区域数，只有公共结果保存完成才标记 100%。完成后停止动画，系统减少动态效果设置生效。

短暂查询断线保留任务 ID，按 2、4、8、10 秒间隔重试同一个 GET 查询，不自动重复上传。队列满保留所选图片；失效任务、授权问题和图片错误提供明确中英提示。页面和 API 文档共享语言偏好；结果 JSON 保持 API 原始数据。

网页在结果旁格式化展示 JSON 并允许复制，支持普通 HTTP 下的复制回退方式；标注 PNG 仍可下载。框绘制、页面缩放、语言切换、JSON 格式化与复制由浏览器完成，原图检测与字体算法保持原有处理流程。

19 项后端测试通过，其中新增验证 FIFO 顺序与真实位置、容量限制、完整结果保存后的 100% 状态、实际模型处理阶段、单任务失败后继续排队任务，以及重启任务的错误状态。本次未训练新字体模型，不改变历史字体精度结论。

界面名称调整为小号 `Glyph`，主页与 API 文档使用统一的红底白字 SVG 图标，已移除作者署名。

最终桌面/手机浏览器验证通过：真实队列从第 8 位降至第 7 位；短暂阻断 GET 后继续同一个任务；完成前未出现 100%；两种 JSON 复制方式与原结果完全相同；新文件和错误输入不会留下旧结果；中英切换、API 文档、PNG 下载、红底 fg 图标与 18 px Glyph 标题均已检查。详情见 [浏览器记录](ui-validation/BROWSER_QA.json)。

页头样式后续更新：恢复完整项目名 `Flux Glyph`，主标题桌面 40 px、手机 32 px，前缀 Flux 使用浅灰色。右上角使用紧凑的中文 / EN 双按钮，取消原下拉框及旁边文字。最新页头外观记录见 `ui-validation/HEADER_QA.json`；之前的浏览器报告保留为当时功能验证记录。
