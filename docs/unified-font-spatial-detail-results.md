# 统一字体模型：横向细节结构试验结果

2026-09-14，本地 MPS 完成 `spatial-detail-v1` 的固定 2,400 步训练，优化器用时 1,373.7 秒。短文字正确覆盖有所增加，但安卓错误命名和未知字体误报高于线上 R22，**不晋级、不发布**。线上健康检查仍返回 `r22-unified-font-retention-v1-preview`。

## 这次改变了什么

将单个 CNN 的空间汇聚从 `4×4` 改为 `4×16`，保留更多主干特征的横向位置。第一层 style 映射从 2,048 维输入增为 8,192 维，参数量从 1,450,938 增为 3,810,234；全部字体仍共用同一个分类头和字号头。完整设计及初始化数值验证见[结构试验说明](unified-font-spatial-detail-training.md)。

从 R22 权重继承初始化，保持上一轮 `native-pairs-v1` 的损失、样本、种子、步数和标称学习率。最终完整采样记录与上一轮逐字段相等；四组参数均更新，新横向子格的系数确实独立学习。参数化变化也会改变优化动态，不能把增益严格归因于空间细节本身。

## 固定 CAL 结果

以下是相同 18,672 个校准视图的结果。视图含同一原生区域的不同版本，不代表同等数量的独立截图。CAL 已反复使用，不能作为盲测准确率。所有判断仍使用原固定评分、间距和多图块一致性要求。

| 指标 | 线上 R22 | 上一轮 native-pairs | 本轮 spatial-detail |
| --- | ---: | ---: | ---: |
| 短文字正确命名 / 3,055 | 1,607 | 1,585 | 1,652 |
| 短文字正确覆盖 | 52.60% | 51.88% | 54.08% |
| 全部正确命名 | 10,554 | 10,516 | 10,640 |
| 全部错误命名 | 517 | 573 | 542 |
| 命名精度 | 95.33% | 94.83% | 95.15% |
| 未知字体被错误命名 / 2,551 | 389 | 419 | 410 |
| iOS 正确命名 / 错误命名 | 6,208 / 61 | 6,184 / 64 | 6,227 / 61 |
| Android 正确命名 / 错误命名 | 4,346 / 456 | 4,332 / 509 | 4,413 / 481 |
| Android 错误命名为 PingFang／SF Pro／Helvetica | 27 | 43 | 38 |

正确覆盖指全部已知字体视图中，通过固定判断条件并被正确输出名称的比例；命名精度指通过这些条件而输出的名称中，正确名称的比例。没有通过条件的区域不计入命名数，因此覆盖增加并不等于精度增加。

相对 R22，短文字净增加 45 个正确命名，即约 1.47 个百分点；全部正确命名净增加 86 个。但全部错误命名增加 25 个，其中未知字体误报净增加 21 个。iOS 汇总错误数保持 61，不能据此声称所有 iOS 字体均未退步；仍有特定字体覆盖下降。

## 为什么不发布

本轮通过原 46 项中的 41 项、新增 7 项中的 3 项，安卓系统字体误报保护也未通过。短文字目标至少为 1,669 个，本轮还差 17 个；短文字未知误报为 164 个，高于 161 个上限。整体未知拒绝、Android 命名精度与未知拒绝、Long Cang 和 Kaiti SC 的覆盖也未满足原要求。详细失败项保存在运行目录的 `report.json`。

训练日志中相同 24 个记录批次的平均损失从 1.2793 降至 1.1225；这是训练过程抽样记录，不是全训练集评估，更不能替代 CAL 的误报检查。结果支持继续研究这类结构，也说明拟合变好未解决未知字体边界问题。

未执行本轮 ONNX 导出、开发集评估或部署；TEST 保持封存。发布门槛和运行时规则均保持原样。
