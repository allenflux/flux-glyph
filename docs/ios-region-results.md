# R16 区域字体模型验证

本地 Docker 的 `http://localhost:9000/` 已运行 `r16-ios-region-v1`。保留 PP DB 文字区域定位；字体及字号由区域 CNN 预测，颜色从原图测量。运行时不做文字识读、逐字切分或参考字库匹配。页面提供可独立运行的字体 ONNX 下载包与使用说明。

## 完整截图验证

对同一组 100 张 iOS Simulator 原始 PNG、1,097 个真实区域重新运行定位和识别，以几何位置配对原生字体真值。测试程序主动禁止识字器、CTC 解码、分字及旧字体分类器，实际调用次数均为零。

| 指标 | R15 单字网络 | R16 区域网络 |
| --- | ---: | ---: |
| 正确字体名 | 811 | 891 |
| 错误字体名 | 0 | 20 |
| 待确认 | 286 | 186 |
| 已输出字体名的准确率 | 100% | 97.80% |
| 全部区域中正确命名占比 | 73.93% | 81.22% |
| 漏检／额外框 | 0／0 | 0／0 |

R16 返回字体名称的覆盖率为 83.04%。这增加了可输出结果的区域，也引入了误判，不能写成各项准确率都优于旧版。

字号可估计 911 行，其中 908 行相对误差不超过 10%；平均绝对误差 1.052 px，平均相对误差 1.83%。字号是截图像素 em，不是 iOS pt；不提供未经校准的置信区间。颜色可估计 1,096 行，全部与标注的可见 RGB 一致；另 1 行无法可靠估计。

## 训练、导出与使用验证

实际训练来源为 1,000 张受控原生模拟器截图：800 张训练、100 张校准、100 张固定回归测试，共 11,016 区域。完成 3,000 次参数更新，校准选择第 3,000 步；所有训练区域均被采样。原生区域框下的独立分类测试为 895 个正确名称、19 个错误、183 个待确认，与上表包含定位误差的结果分别报告。

初次 ONNX 导出在 GroupNorm 归约处超出预先设定的数值容差。稳定导出使用 float64 中间归约后转回 float32；训练权重、输入输出格式、原 PyTorch 参考及容差均保持不变，最终通过全部比较。稳定模型在 1,097 行完整截图上的字体决定与初次导出逐行一致。详细证据见 [数值一致性说明](region-onnx-parity.md)。

最终字体模型 SHA256：`9fde0988dd6e0fe52fb8cacbdd96d1456eabf01ce3a4b431de9ebfd982f3d304`。

实际访问 Docker API 上传原始截图，结果声明 `ocr_performed: false`，各区域文字为 null、单字列表为空。实际下载 1,361,627 字节的字体 ZIP，核对 ZIP 及内部文件 SHA，解压到项目目录外后运行 `predict.py` 成功，字体与 RGB 颜色均符合所选示例的原生标注。

Python 功能套件 320 项通过；另 14 项依赖 PyTorch 的测试在训练环境通过。真实 Chrome 桌面／手机上传、队列、区域详情、PNG 下载、JSON 复制、中英切换和模型下载卡均通过。服务健康检查正常，检查时容器内存约 298 MiB；这是一次观测，不是峰值资源保证。

## 范围限制

截图是原生 iOS Simulator 中运行的受控生成页面，测试分组也曾用于前版验证，属于固定回归集，不是新的盲测或第三方应用真机准确率。

跨渲染环境表现仍明显不足：67 张历史桌面渲染样本中，21 个正确名称、29 个错误名称、9 个已知字体待确认、2 个未知字体拒识、6 个检测数量不符。14 个未知字体样本中有 11 个被误命名、2 个拒识、1 个检测数量不符。最后一项不能算作成功拒识。这组回归没有用于修改模型或门槛，说明当前版本不能可靠处理未知字体，不能将模拟器成绩泛化到任意截图。
