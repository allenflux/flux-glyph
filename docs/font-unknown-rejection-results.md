# R19 未知字体拒识结果

R19 增加独立的神经网络拒识模型。用户提供的两处安卓手写文字缩略图均从 PingFang 候选变为“未知字体”；同批检查中的正常苹方标题和正文保留 PingFang。原图颜色继续返回，未知字体不返回字号。缩略图中的具体字体身份未经验证，因此这四例仅作定性回归。

主字体/字号 ONNX 与 R17 完全相同；新增拒识网络在本机训练，服务器只接收 Git 中的代码与模型。没有引入文字识读、字形参考匹配或根据手机系统强制指定字体的规则。

## 固定留出评估

训练及校准未使用下表四个未知字体族。60 张完整原生模拟器截图中有 360 个未知字体区域和 360 个已知区域；检测全部配对成功，没有漏检或额外框。

| 未知字体族 | 区域 | 成功拒识 | 拒识率 |
|---|---:|---:|---:|
| Wawati SC | 75 | 68 | 90.7% |
| Libian SC | 74 | 74 | 100.0% |
| Chalkboard | 105 | 98 | 93.3% |
| Seravek | 106 | 50 | 47.2% |
| 合计 | 360 | 290 | 80.6% |

360 个新已知字体区域均通过拒识检查。仍有 70 个未知区域显示已知字体候选，其中 61 个通过原分类门槛；主要缺口是外形相近的无衬线字体 Seravek。不能宣称已解决所有未知字体或所有安卓字体的误判。

原 R17 的 100 张完整截图、1,104 个已知区域另作复用回归：

| 指标 | R17 | R19 |
|---|---:|---:|
| 检出区域 | 1,104 | 1,104 |
| 已接受且字体正确 | 1,013 | 1,011 |
| 已接受但字体错误 | 1 | 1 |
| 未输出已接受名称 | 90 | 92 |
| 可测颜色且在容差内 | 1,104 | 1,104 |

两处原本正确的区域被新网络误拒：一个 PingFang HK、一个 Helvetica；没有新增已接受的错误字体名。两个已知测试来源合计 1,464 个区域，误拒 2 个（0.14%）。其中系统字体共 682 个，误拒 2 个。保留的区域沿用原字体分数及字号模型。

原生标注裁图与检测框裁图的边界不同，前者的分类正确数不应直接与整图端到端正确数混用；机器报告分别保存两种评估。

## 训练、导出及下载

420 张实际 iOS Simulator 截图包含 5,040 个区域，其中 60 张为额外训练专用手写样本。另使用原 R17 的 train/calibration 作为已知字体来源；其 test 不参与训练。新增及原 R17 数据清单均以 SHA 绑定。数据隔离、原生来源、分区读取、拒识门控及下载测试见代码与 JSON 证据。

独立拒识网络端到端训练 4,000 步，按校准选择第 3,500 步；补充手写样本继续 2,000 步，选择第 2,000 步。最终校准结果为未知拒识 336/360（93.3%）、已知误拒 4/1,453。门槛 `0.9339949198909202` 在测试前固定。校准成绩与最终留出成绩分别报告，测试后未调整门槛。

导出 ONNX 与原 PyTorch GroupNorm 在 1,040 个抽样/数值检查图块、四种 batch 大小上通过数值对照；新旧两个校准来源的全部 1,813 行，训练、PyTorch、ONNX 的拒识结论完全一致。

下载 ZIP 共九个文件，约 2.74 MB；同时提供字体/字号 ONNX 和拒识 ONNX。解压后的独立 `predict.py` 已验证：只用 ONNX Runtime、NumPy、Pillow，安卓手写裁图输出未知、正常苹方裁图保留名称；未知字号为空，颜色保留。
