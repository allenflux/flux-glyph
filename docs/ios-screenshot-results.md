# R15 iOS 单字 CNN 历史验证结果

本文记录 R15 当时的训练、部署和验证，不代表当前区域模型的状态。R16 保留区域定位，去掉文字识读和逐字切分，见 [区域模型](ios-region-font.md)。`compose.ios.yaml` 随当前版本更新，不用于固定复现本文的 R15 部署。

已采集 1,000 张实际 iOS Simulator 截图、完成 5,000 次神经网络参数更新，并在本地 Docker 的 `http://localhost:9000` 运行 `r15-ios-screenshots-v1`。字体、估计字号与文字颜色均已接入网页和 API。Android 未在本轮采集或训练。

数据来自原生采集 App 内生成的页面，真实渲染、simctl 截屏、逐字 CTRun 字体核验。覆盖 8 家族／23 样式；训练 800 张、校准 100 张、测试 100 张，共 119,447 个有效字形。未将桌面合成图、模拟器截图或真机截图混称，也未用设备型号或旧模型预测代替字体真值。

## 100 张测试截图的完整流程

输入整张原 PNG，真正执行 PP 检测、OCR、分字和字体预测；原生标注仅用于事后评分。检测框与真实墨迹框按固定 IoU≥0.5 一对一配对，不按字体或文字挑选预测框。

| 指标 | R14 参考匹配 | iOS 神经网络 |
|---|---:|---:|
| 真实文字行 | 1,097 | 1,097 |
| 正确输出字体名 | 468（42.66%） | 811（73.93%） |
| 错误字体名 | 3 | 0 |
| 待确认 | 626 | 286 |
| 已输出字体名准确率 | 99.36% | 100% |
| 漏检／额外框 | 0／0 | 0／0 |

新版中文 553/697 行输出正确字体、144 行待确认；数字／英文 258/400 行输出正确字体、142 行待确认。所有 286 行待确认原因均为 `incomplete_segmentation`。OCR 按去空白的冻结评估规则全部正确，原样字符串完全一致为 1,089/1,097；这是文字识读指标，不能等同字体准确率。

## 字号与颜色

完整流程中，1,096/1,097 行返回颜色，返回值全部等于已知可见 RGB；808 行返回字号，平均绝对误差 **0.51 px**，平均相对误差 **0.92%**。其余 289 行字号待确认，多数源于字体或分字证据不足。字号是源截图中的像素 em 估计值，不是 OCR 框高，也不是 iOS pt。

作为测量模块的单独检查，用真实字体和真实字形框评估同一测试集：颜色 1,097 行全部正确；字号 1,096 行可估计，平均误差 0.50 px，95% 样本相对误差不超过约 2.39%。这组条件评估不能替代上面的完整流程指标。

## 训练与导出证据

95,559 个训练字形，12,056 个校准字形，11,832 个测试字形。20 轮全部完成，校准集选中第 19 轮、4,750 次更新的权重；执行总次数仍为 5,000。训练抽样、输入与输出 SHA、参数变化均记录于 [JSON 报告](ios-screenshot-results.json)。

使用原生真实字形框的分类测试中，中文逐字准确率 98.46%、整行 697/697 正确；Latin 逐字 95.63%、整行原始首选 399/400 正确。按冻结门槛与完整性检查，Latin 接受 399 行，其中 398 正确、1 错误、1 行因缺字待确认。这里不包含 OCR／分字误差，不能宣传为完整识别率。

ONNX 与 PyTorch 在固定 128 个校准字形上，首选字体和冻结门槛判断全部一致；最大概率误差中文约 1.20×10⁻⁵、Latin 3.60×10⁻⁵。运行依赖只需 CPU ONNX，服务器不加载 PyTorch。

功能验证：255 项 pytest 通过，另 7 项训练测试在独立 PyTorch 环境通过；实际 Docker 浏览器上传测试验证 4 种语言／宽度组合，字号、色块与 JSON 保持一致，未发现浏览器报错。

## 适用范围与回退

这批结果仅代表相同原生采集域下的留出页面；尚无独立第三方 App 真机截图的字体真值测试。未训练字体不能保证拒识：历史 8 个未知 Latin 字体样本中，5 个拒绝、3 个误判；宋体未纳入本版 8 类，在 6 个历史样本中 3 个误判、3 个待确认。历史 67 张桌面受控渲染回归整体为 42 个正确字体名、11 个错误、9 个待确认、5 个正确拒识。因此本地以 iOS 测试版运行，不将这些模拟器结果泛化为所有截图的准确率。

本地模型挂载由 `compose.ios.yaml` 选择，原始 `models/` R14 清单和参考文件保留。回退本地容器：

```sh
docker compose -f compose.yaml up -d --build
```

再次启用 iOS 模型：

```sh
docker compose -f compose.yaml -f compose.ios.yaml up -d --build
```

本轮没有部署到远程服务器。
